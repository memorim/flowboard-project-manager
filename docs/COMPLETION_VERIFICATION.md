## Что подтверждают проверки

- Два независимых PostgreSQL-пула: конфликт версии даёт 200/409, одно приглашение принимается один раз, общий бюджет 20 запросов пропускает 5.
- Роли, чужие пространства, отзыв доступа и SCIM-деактивация проверяются на сервере.
- Сброс ссылки одноразовый, отзывает сессии, оставляет MFA; повтор TOTP/резервного кода отвергается.
- Callback оплаты не является доверенным результатом; сумма и test flag проверяются по merchant API. Повторные callbacks продлевают план один раз. Неопределённый POST восстанавливается тем же ключом.
- Перенос SQLite в отдельную PostgreSQL сверяет содержимое всех таблиц и не перезаписывает непустую цель.

## Не является внешней проверкой

ЮKassa в этих тестах использует управляемый merchant API fixture, почта — локальные SMTP/Mailpit. Транзакция в магазине ЮKassa, доставка во внешний почтовый ящик и совместимость с выбранным IdP требуют реквизитов оператора. Эти результаты не заявлены.

Новый полный backend не развёртывался поверх прежнего общего Sites-сервера. Другие проекты и главный README профиля не менялись.

- Общий E2E-прогон Windows: 28 passed, 5 штатно skipped (масштаб только в одном Chromium-проекте), 15 failed до выполнения сценария: `spawn UNKNOWN` при старте Firefox/полного Chromium. Эти 15 не считаются успешными. Обычный Chromium headless shell и WebKit прошли свои сценарии.
- Новые auth E2E — 4 passed. После изменения границы read/write-транзакций повторены 7 критичных API/PostgreSQL-сценариев — все passed.
- Проверка локальных ссылок Markdown: 19 файлов, 0 ошибок.
