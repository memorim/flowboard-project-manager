# Надёжность и проверка демонстрации

Все новые проверки используют вымышленные данные.

- Создание с `Idempotency-Key`: повтор возвращает исходный результат, изменение тела с тем же ключом — 409.
- Серверные страницы по 40 записей (максимум 100), фильтры, измерения на 10 000 синтетических записей: `pnpm measure:scale`, `docs/SCALE_METRICS.json`. Это локальные измерения SQLite, не нагрузочный тест размещённого сервиса.
- Кнопка «Пройти демонстрацию» проводит по реальным операциям учебного приложения.
- E2E: Chromium, Firefox, WebKit; компьютерный и мобильный размеры. `zoom.spec.mjs` отдельно измеряет настоящий браузерный масштаб 200% через `chrome.tabs.setZoom` в одноразовом профиле Chromium. Это не CSS zoom.
- Поля и кнопки имеют минимальную цель 24 × 24 CSS px; проверяются фокус, Escape и отсутствие горизонтального переполнения при 320/640 px. Это проверка конкретных сценариев, а не сертификат соответствия WCAG.
- Сервер пишет JSON в stdout: ID запроса, маршрут без параметров, метод, статус и длительность. Тела, query, cookies и токены исключены. При 5xx интерфейс показывает код обращения. Для сохранения журнала перенаправьте stdout в файл или журнал службы.
- `pnpm backup data/flowboard.db backups/snapshot.db` создаёт проверенную SQLite-копию существующей базы; каталог назначения создайте заранее. Существующий файл назначения не перезаписывается. В stdout — результат, размер, ID и время. Проверяются целостность и внешние ключи. Восстановление проверяйте на отдельной базе.
- Автоматическое расписание копирования и срок хранения не настроены. Размещённая версия использует D1; локальная SQLite-команда не копирует облачную D1.

Flowboard: задачи удаляются в корзину; восстановление сохраняет ID. История полей фиксирует автора, время, версии и значения до/после. Старым данным не приписывается вымышленная история.
