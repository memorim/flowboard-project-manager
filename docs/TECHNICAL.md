# Техническое устройство

Актуальные инструкции: [README](../README.md), [аккаунты](SESSION_AUTH.md), [интеграции](INTEGRATIONS.md), [размещение](DEPLOYMENT.md).

| Вариант | Хранилище | Вход |
|---|---|---|
| GitHub Pages | localStorage браузера | выбор участника локального демо |
| Полный Node-сервер | SQLite или PostgreSQL | пароль, подтверждение почты, необязательная MFA |
| Прежний размещённый адаптер | D1 | аккаунт платформы; новые Node-интеграции отдельно |

`src/flow-api.ts` проверяет пространство и права, вызывает `flow-reads.ts`, `flow-workspaces.ts`, `flow-tasks.ts`. Контракт хранения — `SqlDB`, реализации — `server/sqlite-adapter.ts` и `server/postgres.ts`. PostgreSQL использует параметризованные запросы и явную адаптацию ограниченного набора SQL проекта. Это не универсальный SQL-транслятор.

Транзакция Node включает проверку квот и изменение. PostgreSQL блокирует workspace для записи и строки членства; SQLite сериализует асинхронные операции одной connection. CAS версии предотвращает скрытое перезаписывание. SQL-триггеры контролируют назначение и право записи; задача, история и активность изменяются вместе. JSON-тела до 16 KiB, Zod отвергает неизвестные поля, проверяет даты/enums/ссылки.

Каждый endpoint проверяет workspace. Интеграции доступны владельцу; SCIM bearer связан с одним workspace. Accounts сохраняются глобально, права — в memberships. SCIM-деактивация не удаляет чужие пространства и глобальный аккаунт.

Работа с сетью вынесена за транзакции БД: SMTP outbox и сверка платежей используют lease и ограниченные попытки. Критичные изменения плана и одноразовых токенов фиксируются транзакционно. Подробнее и остаточные условия — в документах выше.
