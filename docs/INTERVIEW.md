# Flowboard: показать и объяснить

## Показ за две минуты
Создать пространство → проект → одноразовое приглашение → задача → два редактора открывают одну версию → показать конфликт и сохранённый черновик → наблюдатель без прав записи → отзыв доступа. Для самостоятельного просмотра доступна общая демонстрация; для отдельных команд нужен вход через ChatGPT.

## Вопросы и ответы
1. **Что делал?** Клиент React/TypeScript, API, модель SQLite/D1, роли, приглашения, проверки и демо. Файлы: src/App.tsx, src/flow-api.ts, server/db.ts, tests/workspaces.test.ts.
2. **Где проверяется доступ?** В flowApi по workspace и memberships. Проекты и исполнители проверяются внутри выбранной команды; скрытое пространство даёт 404.
3. **Зачем версия?** PATCH/DELETE несут ожидаемую version. SQL меняет запись только при совпадении; устаревшая форма получает 409, без потери введённого текста.
4. **Как связаны задача и журнал?** Одна batch-транзакция. Событие появляется лишь при фактическом изменении; ошибка события откатывает задачу.
5. **Как устроены приглашения?** Случайный токен, в БД SHA-256, срок 7 дней, однократное принятие. Повторное принятие не возвращает отозванный доступ.
6. **Почему два хранилища?** localStorage позволяет открыть интерфейс на Pages; SQLite удобна локально; D1 даёт постоянные записи онлайн. Командные функции доступны на сервере.
7. **Можно ли доверять X-Demo-Actor?** Только внутри локального учебного запуска. Hosted-адаптер его игнорирует и получает identity от Sites.
8. **Какие тесты самые важные?** Изоляция, readonly, повтор приглашения, конфликт двух записей и откат при сбое журнала. UI повторяет путь в трёх контекстах, без людей.
9. **Как проверял надёжность?** Восстановил временную SQLite и сверил таблицы/целостность. Локальные замеры записаны с условиями, без обещаний production-производительности.
10. **Что упрощено?** Нет realtime, восстановления удалённого и полного аудита редакций. До этого этапа изменения отображаются после загрузки/кнопки обновления; дальше можно добавить события и историю.
