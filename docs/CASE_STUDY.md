# Flowboard: работающая доска и общая серверная демонстрация

## Задача и мой вклад
Самостоятельный портфолио-проект управления небольшими проектами, использовавшийся реальными пользователями. Разработаны интерфейс, адаптивная доска, API, SQLite, общая схема валидации, тесты и размещённый вариант. Метрики аудитории и коммерческие результаты не заявляются.

## Пользовательский путь
Обзор → создание задачи → редактирование → назначение и статус → фильтры → календарь → команда → фактическая лента действий. Изменения сохраняются после перезагрузки, а счётчики и прогресс следуют за задачами.

## Решения
1. Общая Zod-схема исключает разный набор допустимых полей в API и браузерной версии. Ссылки проверяются до записи, неизвестные поля отвергаются.
2. Прогресс выводится из done/total, включая нулевое количество задач. Смена статуса на уже существующий не создаёт лишнее событие.
3. В localStorage задачи и активность лежат в одном объекте; старые данные мигрируют, повреждённые не затираются. Это удобное индивидуальное демо, без межпользовательской синхронизации.
4. [Серверная демонстрация](https://memorim-flowboard-live.amusedcorgi34.chatgpt.site) использует постоянную D1. Запись задачи и события идёт через batch-транзакцию. Sites выполняет вход через ChatGPT; в общей базе используется псевдоним, без имени/email посетителя.
5. Для мобильной версии доступны обычные select статуса и форма редактирования; drag-and-drop остаётся дополнительным способом на компьютере.

## Подтверждение
API и браузерные тесты покрывают изменение полей, ссылки, статусы, сохранение и журнал. E2E создаёт и редактирует задачу, меняет статус, перезагружает страницу, проверяет пустой поиск, календарь и команду на 1280/390 px. Локальный тест размещённого API проверяет D1, запрет анонимной записи и подмены identity, ошибки JSON/ссылок/размера.

## Ограничения
Общее пространство позволяет любому вошедшему редактировать демо-задачи. Отдельные команды имеют роли owner/editor/viewer, доступ проверяется на сервере. Optimistic locking возвращает 409 при несовпадении версии. Realtime, восстановление удалённого и история всех редакций не реализованы. Локальный Node API доверяет X-Demo-Actor и не предназначен для публичного открытия. Два реальных внешних ChatGPT-аккаунта в этой проверке не использовались.

## Следующий этап: искусственная командная проверка
Владелец создаёт пространство → приглашает редактора → тот создаёт задачу → оба открывают одну версию → принимается одно сохранение → второе получает конфликт с сохранением черновика → наблюдатель читает без права изменения → владелец отзывает доступ. Переходы проверены в отдельных браузерных контекстах, без реальных участников. Учебные роли локального API не являются публичной аутентификацией; размещённая версия получает identity только от Sites.
